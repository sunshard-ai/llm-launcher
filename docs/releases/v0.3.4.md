## Fixed

- Docker diagnostics distinguish an unavailable daemon from a server running Windows containers. Failed or client-only probes no longer imply that container mode must be changed.
- `--port 0` selects a free local port, preferring the engine default. Explicitly occupied ports are rejected during planning. The Windows app chooses a new folder when preparing a replacement plan and preserves earlier deployments.
- Windows commands use a session-owned executable and working directory. Failed process starts restore the interface controls and show a recovery message with the original error under technical details.
- The Windows catalog row displays its profile count, date and update button. Successful updates refresh recommendations.
- New llama.cpp NVIDIA plans enable startup logging at level 4. The pinned server hides library offload messages at its default level 3, even when it is using the GPU.
- llama.cpp GPU verification reads all retained messages for the current container start. Long startup logs can push the offload message beyond the previous 300-line window. The check also preserves evidence written before large amounts of stderr output.
- GPU messages from earlier container starts are excluded from the check.
- Cached runtime images are inspected locally before any download. Compose startup uses `--pull never`, avoiding unnecessary registry credential lookups for cached digests. Missing images are still downloaded and the recorded image ID is checked. Credential-helper failures during a required download now include a suggested next check.

## Diagnostics

The Windows app adds **Model from disk…** for downloaded Safetensors folders and GGUF files. The original Hugging Face URL supplies the pinned revision. Preparing the plan verifies and copies the selected files. **Attach weights…** and `import-weights --dir PLAN --from PATH` support existing compatible plans. Original files and existing caches are preserved. Plan schemas and runtime arguments are unchanged by this import workflow.

Use `llm-launcher logs --all --dir ./my-model` to collect the full retained startup log.

Both fixes passed two start/test/status/down cycles on an RTX 4080 SUPER with Qwen3 0.6B Q8_0 at context 4096. Both starts reused the cached runtime image, confirmed 29/29 layers on GPU and returned chat responses. Complete startup took 59.493 and 57.217 seconds; separate smoke requests took 733 and 487 ms. Simulated Docker and local API lifecycle tests also passed. See the [build report](https://github.com/sunshard-ai/llm-launcher/blob/main/docs/BUILD_REPORT.md) for test scope and earlier results.

For an older llama.cpp GPU plan created with quiet startup logging, create a new plan and reuse the verified GGUF file. The launcher reports this recovery step explicitly when the runtime's log level hides GPU details.
